# Concept Assistant Reference

本文件补充 `concept-assistant` 的边界、折叠策略与自检清单，用于保证输出更“能读懂、能复述、能继续深挖”。

## 适用范围

- **适用**：技术概念、机制、流程、协议、工具、设计模式等的通俗解释与结构化讲解。
- **不适用**：需要实时查证的数据（最新版本特性、最新 benchmark、具体厂商价格/政策）。此类内容必须明确“以官方文档/实测为准”。

## 章节裁剪规则

- **纯描述性概念**：优先只写 What；How/Why 仅在确有机制或价值讨论时再加。
- **工具/解决方案类**：Why（解决什么问题、何时使用）优先，其次再补 How（核心工作方式）。
- **过载控制**：当 How 细节过深时，先给核心链路 + 关键结论，把实现细节折叠或留作后续文章。

## 折叠策略

- **不折叠**：一句话定义、关键结论、核心链路、关键对比结论。
- **可折叠**：边缘案例、实现细节、推导过程的“长证明”、延伸阅读与历史背景。

## 类比使用准则

- **默认不类比**：能用直观语言说清的，不要类比。
- **类比必须可对齐**：类比要映射到 1-2 个关键点，避免“看似好懂但误导”。

## 自检清单（输出前）

- 格式符合 `writing-style` 规范（如标题无表情符号）
- 一句话定义足够短、读者能复述
- 术语首次出现已给一句话解释
- 核心链路不折叠，扩展内容已折叠（如适用）
- 章节裁剪合理：不为了凑结构硬加段落
