# Content Refiner

本技能旨在帮助用户对技术文档（特别是 OSTEP 等学习笔记）进行“凝练”，使其更加干练且易于复习，同时不失初学者的引导性。

## 指令 (Instructions)

当用户要求“凝练”某部分内容时，请遵循以下原则：

1.  **结构化重组**：将冗长的段落转化为标题、列表（Bullet points）或引用块（Callouts）。
2.  **保留核心**：
    *   **必须保留**：原文中的所有图片（`![[...]`）、代码块（` ``` `）和表格。
    *   **酌情保留**：保留必要的引导性文字或类比，确保初学者能够理解概念的背景和意义。
3.  **代码处理**：
    *   保持代码逻辑不变。
    *   **翻译注释**：将代码块中的英文注释翻译为中文，以增强可读性。
4.  **适度凝练**：
    *   删除重复的描述或过于口语化的修饰词。
    *   使用专业术语（如“页错误”、“水位线”等）并保持一致性。
    *   避免过度删减导致逻辑断层。

## 示例 (Examples)

### 输入 (原文)
> 为了保证有少量的空闲内存，大多数操作系统会设置高水位线（High Watermark，HW）和低水位线（Low Watermark，LW），来帮助决定何时从内存中清除页。原理是这样：当操作系统发现有少于 LW 个页可用时，后台负责释放内存的线程会开始运行，直到有 HW 个可用的物理页。

### 输出 (凝练后)
> ### 水位线机制 (Watermarks)
> 操作系统通过设置 **高水位线 (HW)** 和 **低水位线 (LW)** 来触发内存释放：
> - **触发条件**：当可用内存少于 **LW** 时，后台线程开始运行。
> - **停止条件**：直到可用内存达到 **HW**，后台线程进入休眠。
