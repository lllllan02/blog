# Content Refiner

本技能旨在帮助用户对技术文档（特别是 OSTEP 等学习笔记）进行“凝练”，使其更加干练且易于复习，同时不失初学者的引导性。

## 指令 (Instructions)

当用户要求“凝练”某部分内容时，请遵循以下原则：

1.  **结构化重组**：
    *   将冗长的段落转化为标题、列表（Bullet points）或引用块（Callouts）。
    *   使用 Callout (`::: [!type] Title`) 来突出重点结论、收纳扩展知识或标记陷阱（如 `[!warning]`）。

2.  **保留核心 (Critical Retention)**：
    *   **必须保留**：原文中的所有图片（`![[...]`）、代码块（` ``` `）、表格以及核心公式。
    *   **图表上下文**：图表周围的解释性文字不能全删，必须保留核心结论（图表说明了什么）。
    *   **关键机制**：对于算法（如 Clock 算法），保留完整的步骤逻辑和判断分支；对于机制（如水位线），保留触发条件和阈值。

3.  **深度与因果 (Depth & Causality)**：
    *   **拒绝过度简化**：不要为了简洁而牺牲逻辑完整性。
    *   **保留因果**：在对比分析时，不仅要给出结论（如“LRU 优于 FIFO”），必须保留“为什么”（如“因为 LRU 能保留热点页，而 FIFO 可能会踢出它们”）。
    *   **异常与边界**：保留关键的异常情况（如 Belady 异常）及其成因。

4.  **代码处理**：
    *   保持代码逻辑不变。
    *   **翻译注释**：将代码块中的英文注释翻译为中文，以增强可读性。

5.  **适度凝练**：
    *   删除重复的描述、过于口语化的修饰词或无关的背景铺垫。
    *   使用专业术语（如“页错误”、“水位线”等）并保持一致性。
    *   **自检**：凝练后的内容是否足够支撑用户理解核心概念？如果删除了某句话导致逻辑跳跃，请恢复它。

## 示例 (Examples)

### 输入 (原文)
> 为了保证有少量的空闲内存，大多数操作系统会设置高水位线（High Watermark，HW）和低水位线（Low Watermark，LW），来帮助决定何时从内存中清除页。原理是这样：当操作系统发现有少于 LW 个页可用时，后台负责释放内存的线程会开始运行，直到有 HW 个可用的物理页。

### 输出 (凝练后)
> ### 水位线机制 (Watermarks)
> 操作系统通过设置 **高水位线 (HW)** 和 **低水位线 (LW)** 来触发内存释放：
> - **触发条件**：当可用内存少于 **LW** 时，后台线程开始运行。
> - **停止条件**：直到可用内存达到 **HW**，后台线程进入休眠。
