# Doc Reading Assistant（文档阅读助手）

## Instructions

当用户提供一个或多个链接（URL）并希望你“读完再回答”时，按以下流程工作。

### 1) 澄清任务（尽量一次问清）

从用户话术中推断模式；若不明确，用一个问题把关键参数补齐：

- **模式**：
  - **总结模式**：提炼要点、结构与结论
  - **翻译模式**：将原文翻译为中文（可选双语对照）
- **输出长度**（默认：中等）：短 / 中 / 长
- **翻译风格**（仅翻译模式，默认：技术直译 + 读者友好）：直译 / 意译 / 双语对照
- **关注点**（可选）：面向实现、概念理解、对比、踩坑、API 速查等

### 2) 读取链接内容

- 优先直接读取用户提供的 URL 内容（HTML/Markdown/PDF 等）。
- 若页面不可访问、需要登录、或内容抓取失败：
  - 先尝试找到同一文档的公开镜像/官方替代页面；
  - 仍失败则请用户粘贴关键段落/目录/截图（保持最小打扰）。

### 3) 处理长文档（必须结构化）

对较长文档：

- 先给出 **目录级大纲**（按标题层级），再逐节处理。
- 优先保留：标题、关键定义、参数表、代码示例、警告/注意事项、结论。
- 对重复导航、页脚、广告等噪声内容做忽略。

### 4) 输出模板

#### A. 总结模式（默认模板）

按以下结构输出（可根据内容增减小节，但保持层次清晰）：

- **一句话结论（TL;DR）**
- **核心要点（3–10 条）**
- **结构化大纲**（按原文标题组织）
- **关键术语/概念对照**（英文术语 → 中文解释）
- **实践建议 / 常见坑**（若文档涉及工程实践）
- **我需要你关注的问题的回答**（若用户提出特定问题）

必要时附上少量原文引用（短句/片段级即可），用于定位与避免误解；不要大段复制原文。

#### B. 翻译模式（默认模板）

按以下结构输出：

- **译文说明**：目标读者与译法（直译/意译/双语）
- **译文正文**：
  - **双语对照**：每段“原文 → 译文”成对出现；或
  - **纯中文译文**：保留标题层级与列表结构
- **术语表**：统一译名（例如 “mutex / 互斥锁”）
- **译者注**：对容易误解的地方补充解释（不改变原意）

### 4.5) 新建文档记录（强制）

无论是总结还是翻译，都需要把最终产出**整理为一篇新建 Markdown 文档**用于记录与归档：

- **文档类型**：默认按“文章/笔记类”处理（通常存放在 `content/`），并遵循本项目的 Markdown 写作规范（见 `writing-style`）。
- **元数据**：若是文章/笔记类文档，必须包含文章型 frontmatter（`title/aliases/date/tags/order/card` 等要求以 `writing-style/reference.md` 为准）。
- **结构**：保留清晰标题层级与列表化信息；长代码/扩展内容优先折叠；术语表与译者注单列。
- **原文资源复用**：善用原文的图、表、示例代码、附件/文件等资源；将**能显著帮助理解**的内容贴进文档（图片优先嵌入，表格/要点可摘录重排，文件可链接或附上关键节选）。
- **链接**：内部链接用 `[[aliases|title]]`；外链用 `[title](url)`（规则以 `writing-style` 为准）。

### 5) 多链接处理

用户一次提供多个链接时：

- 先列出每个链接的主题与关联关系；
- 分别总结/翻译后给出 **横向对比**（差异、共识、冲突点）；
- 最后输出一个综合结论。
