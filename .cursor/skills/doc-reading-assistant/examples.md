# 文档阅读助手：示例

下面示例用于展示同一个技能在“总结模式 / 翻译模式 / 多链接对比”下的典型交互与输出形态。示例为模板风格，实际输出应以用户提供链接内容为准。

## 示例 1：总结模式（英文长文档）

### 用户输入

请阅读这个文档并给我总结一下，重点关注设计动机和常见坑：`https://example.com/very-long-doc`

### 期望输出（摘要）

- **一句话结论（TL;DR）**：该文档主要解释了 X 的设计目标是在 Y 约束下实现 Z，并给出了推荐配置与避坑指南。
- **核心要点**：
  - X 的核心抽象是 A/B/C，其中 B 是性能与一致性的关键权衡点
  - 默认配置适用于大多数场景，但在 P 情况下必须显式调整 Q
  - 文档特别强调了两个坑：R（会导致错误行为）与 S（会导致性能退化）
- **结构化大纲**：
  - Overview：X 解决的问题与不解决的问题
  - Concepts：A/B/C 的定义与关系
  - Configuration：关键参数与推荐值
  - Pitfalls：常见误区与诊断方法
- **关键术语/概念对照**：
  - consistency：一致性（此处指……）
  - trade-off：权衡
- **实践建议 / 常见坑**：
  - 如果你在生产环境启用 Q，务必同时开启 T 来避免 R
  - 当出现 S 的症状时，先检查 U 指标再调整 V
- **原文资源（图/表/文件）**：
  - 把原文中解释核心机制的流程图嵌入到文档，并在图下补一句“该图展示了……”
  - 将关键参数表转换为 Markdown 表格，便于检索与复用
  - 对原文提供的示例仓库/附件文件，记录用途与链接，必要时摘录关键片段

## 示例 2：翻译模式（双语对照 + 术语表）

### 用户输入

帮我把这个英文文档翻译成中文，要求双语对照，术语统一：`https://example.com/api-doc`

### 期望输出（节选）

- **译文说明**：采用技术直译为主，遇到歧义处提供译者注；保留所有参数名、代码块与命令。
- **译文正文（双语对照）**：

原文：Introduction  
译文：简介

原文：This API provides ...  
译文：该 API 提供了……

原文：Parameters  
译文：参数

原文：`timeout` (milliseconds): The maximum time to wait...  
译文：`timeout`（毫秒）：最大等待时间……

- **术语表**：
  - endpoint：端点
  - request payload：请求负载
  - idempotent：幂等
- **译者注**：
  - 文中 “idempotent” 指“重复调用结果一致”，并不等同于“无副作用”。

## 示例 3：多链接（分别总结 + 横向对比）

### 用户输入

请分别阅读并总结这两篇文章，然后对比它们观点差异：  
1) `https://example.com/design-a`  
2) `https://example.com/design-b`

### 期望输出（摘要）

- **链接 1 定位**：从工程落地角度讨论 A，重点在可观测性与默认配置。
- **链接 2 定位**：从理论与边界条件角度讨论 A，重点在一致性与极端场景。
- **分别总结**：
  - 链接 1：……
  - 链接 2：……
- **横向对比**：
  - **共识**：都认为 B 是关键瓶颈，需要先做 C。
  - **差异**：链接 1 更强调“默认可用”，链接 2 更强调“极端情况下必须做 D”。
  - **可能原因**：两文假设的负载模型不同（链接 1 假设……，链接 2 假设……）。
- **综合结论**：如果你的场景接近……，优先采用链接 1 的方案；若需要覆盖……，必须引入链接 2 的约束与措施。
