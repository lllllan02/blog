# Condense Text

将冗长的技术博客文章凝练为高信息密度版本，同时严格保留原文的技术细节、关键数据和逻辑递进关系。

## 核心原则 (Core Principles)

- **保留关键数据**: 绝对不删除代码块、图片链接、表格、数学公式 (LaTeX) 和特定的技术术语定义。
- **逻辑完整性**: 凝练不等于总结。保留文章的层层递进、因果关系和深入分析，不要将推导过程缩减为结论。
- **去除废话**: 删除无意义的过渡句（如“让我们来看看...”）、冗余修饰词、重复解释和过度口语化的表达。
- **结构重构**: 主动优化原文结构。提取核心概念并补充小标题，将松散内容重组为逻辑清晰的模块，不要机械地按原文顺序缩写。
- **合理分段与排版**:
  - 多用自然段落，保持文本连贯，避免过度碎片化。
  - 仅在包含多个独立概念时使用列表或小标题：
    - 单条内容较短（如一两句话）：使用无序/有序列表。
    - 单条内容较长（包含多句话或代码块）：使用小标题（如 `####`）分割，避免列表项臃肿。
- **主动语态**: 使用简练的主动语态替代被动语态。

## 处理流程 (Workflow)

### 1. 分析与识别
- 扫描全文，标记必须原样保留的技术工件（代码块、图片、表格、公式）。
- 确认文章的论证结构（如：问题 -> 原因分析 -> 尝试方案 -> 最终方案），确保逻辑链不断裂。

### 2. 重写与结构优化
- **精简表达**: 将长难句改写为短句。
  - *示例*: "The function is designed in such a way that it takes an input and returns an output." -> "The function takes an input and returns an output."
- **保留推导**: 解释“为什么 A 导致 B”时，保留中间的机制解释。
- **自然过渡**: 简单的并列项尽量用连贯的句子自然过渡，而非直接转为列表。

### 3. 格式检查
- **Markdown 结构**: 保持原有的标题层级（H2, H3 等），不要合并章节导致层级混乱。
- **引用与链接**: 确保所有 `[[...]]` 和 `[...] (...)` 链接完好无损。
- **Callout 保留**: 保留原文 Callout，并统一使用本项目格式（如 `::: [!note]`）。
- **中英文空格**: 遵循 `writing-style` 规范，保持中英文之间的空格。

## 示例 (Examples)

### 示例 1：去除口语化过渡，保留逻辑
**原文**:
> 好了，既然我们已经了解了基本的原理，那么接下来我们可能会问，为什么这种方法在并发高的时候会失效呢？其实原因很简单，主要是因为锁的竞争太激烈了，导致 CPU 把大量时间花在了上下文切换上。

**凝练后**:
> 在高并发场景下该方法失效，原因是锁竞争激烈导致 CPU 大量时间消耗在上下文切换上。

### 示例 2：连贯分段代替列表
**原文**:
> 这个库提供了多种功能。首先，它可以进行数据验证。其次，它支持格式转换。最后，它还能处理错误报告。

**凝练后**:
> 这个库支持数据验证、格式转换和错误报告等功能。

## 注意事项 (Notes)
- **不要过度概括**: 如果解释了具体算法步骤，保留关键步骤描述，不要只写“实现了算法”。
- **不要变成大纲**: 凝练后的内容必须是一篇可读的**文章**，而非骨架大纲。
- **保持原意**: 确保技术准确性不受影响。
