# Condense Text Skill (文字凝练技能)

本技能旨在帮助用户将冗长的技术博客文章凝练为高信息密度的版本，同时严格保留原文的技术细节和关键数据。

## 核心原则 (Core Principles)

1.  **保留关键数据 (Preserve Artifacts)**：绝对不删除代码块、图片链接、表格、数学公式 (LaTeX) 和特定的技术术语定义。
2.  **去除废话 (Remove Fluff)**：删除过渡性语句（如“在本文中我们将讨论...”）、冗余的形容词、重复的解释和口语化的表达。
3.  **结构化 (Structure)**：将长段落转化为无序列表或有序列表，提高可读性。
4.  **主动语态 (Active Voice)**：使用简练的主动语态替代被动语态。

## 处理流程 (Workflow)

当用户请求凝练文章时，请按以下步骤操作：

### 1. 分析与识别 (Analyze & Identify)
-   **识别技术工件**：扫描全文，标记所有代码块 (```...```)、图片 (`![...] (...)`)、表格 (`|...|`) 和公式 (`$...$`)。这些内容必须原样保留。
-   **识别冗余内容**：找出仅仅是“为了流畅”而存在的句子，如“这就引出了下一个问题...”、“正如我们在上一节看到的...”。

### 2. 重写与凝练 (Rewrite & Condense)
-   **段落重写**：将每个段落的核心观点提取出来，用更短的句子重写。
    -   *原句*："The function is designed in such a way that it takes an input and returns an output."
    -   *凝练*："The function takes an input and returns an output."
-   **列表化**：如果一个段落包含三个或以上的并列项，将其转换为列表。
-   **合并**：如果多个短句表达同一个意思，将其合并为一个长句（如果这能减少词数且不影响清晰度）。

### 3. 格式检查 (Format Check)
-   **Markdown 结构**：保持原有的标题层级（H2, H3 等），除非某些层级因内容删除而变得多余。
-   **引用与链接**：确保所有 `[[...]]` 和 `[...] (...)` 链接都保留且正确。
-   **Callout 保留**：如果原文使用了 Callout (如 `> [!NOTE]`)，请保留，除非其内容完全是废话。

## 示例 (Examples)

### 示例 1：去除过渡句

**原文**：
> 在我们深入探讨具体的实现细节之前，让我们先花一点时间回顾一下为什么我们需要这个功能。正如我们在前一章所讨论的，并发控制是极其复杂的。因此，我们需要一种机制来简化它。

**凝练后**：
> 并发控制极其复杂，因此需要一种机制来简化它。

### 示例 2：列表化

**原文**：
> 这个库提供了多种功能。首先，它可以进行数据验证。其次，它支持格式转换。最后，它还能处理错误报告。

**凝练后**：
> 这个库提供以下功能：
> - 数据验证
> - 格式转换
> - 错误报告

## 注意事项 (Notes)

-   **不要过度概括**：如果一段代码解释了具体的算法步骤，不要只说“这段代码实现了算法”，而要保留关键步骤的描述。
-   **保持原意**：凝练不等于改变原意。确保技术准确性不受影响。
-   **中英文空格**：遵循 `writing-style` 规范，保持中英文之间的空格。
