# Condense Text Skill (文字凝练技能)

本技能旨在帮助用户将冗长的技术博客文章凝练为高信息密度的版本，同时严格保留原文的技术细节、关键数据和**逻辑递进关系**。

## 核心原则 (Core Principles)

1.  **保留关键数据 (Preserve Artifacts)**：绝对不删除代码块、图片链接、表格、数学公式 (LaTeX) 和特定的技术术语定义。
2.  **逻辑完整性 (Logical Integrity)**：**凝练不等于总结**。不要将详细的推导过程缩减为一句话的结论。文章的层层递进、因果关系和深入分析必须保留。
3.  **去除废话 (Remove Fluff)**：仅删除无意义的过渡性语句（如“让我们来看看...”）、冗余的修饰词、重复的解释和过于口语化的“大白话”。
4.  **结构化 (Structure)**：将长段落转化为无序列表或有序列表，提高可读性，但不要丢失上下文。
5.  **主动语态 (Active Voice)**：使用简练的主动语态替代被动语态。

## 处理流程 (Workflow)

当用户请求凝练文章时，请按以下步骤操作：

### 1. 分析与识别 (Analyze & Identify)
-   **识别技术工件**：扫描全文，标记所有代码块 (```...```)、图片 (`![...] (...)`)、表格 (`|...|`) 和公式 (`$...$`)。这些内容必须原样保留。
-   **识别逻辑链**：确认文章的论证结构。例如：问题 -> 原因分析 -> 尝试方案 -> 最终方案。这个链条不能断。

### 2. 重写与凝练 (Rewrite & Condense)
-   **精简表达**：将长难句改写为短句，去除“正确的废话”。
    -   *原句*："The function is designed in such a way that it takes an input and returns an output."
    -   *凝练*："The function takes an input and returns an output."
-   **保留推导**：如果一段话在解释“为什么 A 导致 B”，不要只写“A 导致 B”，而要保留中间的机制解释。
-   **列表化**：如果一个段落包含三个或以上的并列项，将其转换为列表。

### 3. 格式检查 (Format Check)
-   **Markdown 结构**：保持原有的标题层级（H2, H3 等），不要合并章节导致层级混乱。
-   **引用与链接**：确保所有 `[[...]]` 和 `[...] (...)` 链接都保留且正确。
-   **Callout 保留**：如果原文使用了 Callout (如 `> [!NOTE]`)，请保留。

## 示例 (Examples)

### 示例 1：去除口语化过渡，保留逻辑

**原文**：
> 好了，既然我们已经了解了基本的原理，那么接下来我们可能会问，为什么这种方法在并发高的时候会失效呢？其实原因很简单，主要是因为锁的竞争太激烈了，导致 CPU 把大量时间花在了上下文切换上。

**凝练后**：
> 在高并发场景下该方法失效，原因是锁竞争激烈导致 CPU 大量时间消耗在上下文切换上。

*(注意：保留了“锁竞争”到“上下文切换”的因果链，只是去掉了“好了”、“接下来我们可能会问”等废话)*

### 示例 2：列表化

**原文**：
> 这个库提供了多种功能。首先，它可以进行数据验证。其次，它支持格式转换。最后，它还能处理错误报告。

**凝练后**：
> 这个库提供以下功能：
> - 数据验证
> - 格式转换
> - 错误报告

## 注意事项 (Notes)

-   **不要过度概括**：如果一段代码解释了具体的算法步骤，不要只说“这段代码实现了算法”，而要保留关键步骤的描述。
-   **不要变成大纲**：凝练后的文章应该仍然是一篇可读的**文章**，而不是一份只有骨架的 PPT 大纲。
-   **保持原意**：凝练不等于改变原意。确保技术准确性不受影响。
-   **中英文空格**：遵循 `writing-style` 规范，保持中英文之间的空格。
