# 写作风格规范 (Writing Style Guide)

## 核心原则

### 1. 文档简洁原则 (Conciseness)
- **精炼表达**：在保证知识点讲解清晰、完整的前提下，尽量保持语言简单直接。
- **渐进式阅读**：
    - **折叠扩展**：对于底层原理、源码分析或长代码示例，优先使用 Callout 的折叠语法（如 `::: [!abstract]- 标题`）。
    - **模块化拆分**：如果扩展内容篇幅过大，建议新起一篇文档进行专项讲解，并在当前文档中通过链接引用。
- **列表化结构**：优先使用有序/无序列表替代长段落，提高信息密度。

### 2. 标题与元数据规范 (Metadata)
- **纯文本标题**：所有层级的标题（H1-H6）严禁使用表情符号（Emoji）。
- **Frontmatter 完整性**：每个文档必须包含以下字段：
    - `title`: 页面标题（简洁直观）。
    - `aliases`: 包含一个生成的随机 UUID，用于稳定引用。
    - `date`: 创建日期，格式为 `YYYY-MM-DD HH:mm:ss`。在创建新文档时，必须自动获取当前的系统时间作为该字段的值。
    - `tags`: 标签列表，优先从库文件选择。
    - `order`: 排序权重（数字越小越靠前）。
    - `card`: 布尔值，是否以卡片形式展示（通常为 `true`）。
- **UUID 别名与链接**：
    - **内部链接规范**：当在文档中使用内部链接（双向链接）时，应填写目标文档 `aliases` 中生成的 UUID，而非文件路径，以确保文件重命名或移动后链接依然有效。
- **标签库管理**：
    - 优先从库文件 [.cursor/data/tags.txt](.cursor/data/tags.txt) 中选择标签。
    - 若需新增标签，必须先同步更新到该库文件中。
- **标题命名**：应直接反映内容核心，避免冗长。

### 3. 正文强调与标注 (Emphasis)
- **克制原则**：严禁过度强调。每段文字建议只保留 1-2 处最核心的强调。
- **标注方式**：适度使用加粗（`**文本**`）、下划线（`<u>文本</u>`）或 Callout 块（如 `::: [!tip] \n 内容 \n :::`）。
- **表情符号**：正文内可适度使用 Emoji 作为列表标记，但需保持专业感，禁止堆砌。

### 4. 排版要求 (Formatting)
- **中英文空格**：中英文之间必须保持一个空格（如：Go 语言）。
- **空行规范**：标题与段落、段落与段落之间必须保留一个空行。
- **代码块**：必须指定正确的语言标签（如 ```go）。

## 开发者指令

当执行文档生成任务时：
1. **初始化元数据**：调用工具生成 UUID 并从标签库匹配标签。
2. **内容审核**：根据“文档简洁原则”过滤无关信息。
3. **格式自检**：检查标题是否有 Emoji，中英文是否有空格，空行是否充足。
