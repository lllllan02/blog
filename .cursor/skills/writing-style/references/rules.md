# Writing Rules & Standards

本文件详细定义了本项目 Markdown 文档的各项规范。

## 1. Structure and Style (结构与风格)

### 1.1 完整性与连贯性 (Completeness & Coherence)
-   **拒绝过度凝练 (Avoid Over-Condensing)**：不要将复杂的逻辑压缩成干瘪的结论。解释“为什么”和“怎么做”，而不仅仅是“是什么”。
-   **段落优先 (Paragraphs First)**：对于叙述性、解释性内容，优先使用完整的段落，保证阅读体验的流畅。
-   **列表克制 (List Restraint)**：仅在列举并列项、步骤或特征时使用列表。避免将整篇文章拆解为碎片化的列表项。
-   **精炼而非删减**：去除无意义的“废话”（如“众所周知”），但**保留**所有有助于理解的细节、背景和逻辑推导。

### 1.2 渐进式披露 (Progressive Disclosure)
-   **Callout 策略**：
    -   **克制使用 (Restraint)**：**过多的强调等于没有强调**。仅在绝对必要时使用 Callout。
    -   **重点结论/警告**：使用不折叠的 Callout (`[!tip]`, `[!warning]`)。
    -   **扩展阅读/背景/长代码**：使用**默认折叠**的 Callout (`[!abstract]-`, `[!example]-`)，避免打断阅读流。
    -   **避免滥用**：不要将正文段落全部放入 Callout 中。Callout 应仅用于“跳出”正常阅读流的内容。
-   **标题层级**：
    -   严禁使用 H1（由系统根据 Frontmatter `title` 自动生成）。
    -   仅使用 H2-H4 进行层级划分。
    -   标题中**严禁**使用 Emoji 表情符号。

### 1.3 语气 (Voice & Tone)
-   **专业直接**：保持客观、技术性的语调。
-   **避免过度营销**：关注事实和解决方案，而非推销。

## 2. Metadata Standards (元数据规范)

所有 `content/` 下的文章必须包含以下 YAML Frontmatter 字段：

| 字段 | 必填 | 说明 | 示例 |
| :--- | :--- | :--- | :--- |
| `title` | 是 | 页面标题，简洁直观。概念类可用“中文 英文”格式。 | `协程栈 Goroutine Stack` |
| `aliases` | 是 | **全库唯一**的 UUID v4（小写，带连字符）。用于稳定引用。 | `a1b2c3d4-e5f6-...` |
| `date` | 是 | 创建时间，格式 `YYYY-MM-DD HH:mm:ss`。 | `2023-10-27 10:00:00` |
| `tags` | 否 | 标签列表。 | `[go, concurrency]` |
| `order` | 否 | 排序权重（数字越小越靠前）。 | `1` |
| `card` | 否 | 是否为 Flashcard 知识点（布尔值）。 | `true` |

## 3. Formatting Rules (排版规范)

### 3.1 文本格式
-   **中英文空格**：中文字符与英文字母/数字之间**必须**有一个空格。
    -   ✅ `学习 Go 语言`
    -   ❌ `学习Go语言`
-   **标点符号**：中文语境下使用全角标点（代码块内除外）。
-   **强调**：每段最多 1-2 处加粗 (`**text**`)，避免满篇重点。

### 3.2 代码块
-   **语言标签**：必须指定语言（如 `go`, `python`, `bash`）。
-   **代码折叠**：超过 10 行的代码块，建议使用 `fold` 属性。
    -   ````markdown
        ```go fold="main.go"
        // code...
        ```
        ````
-   **多语言对比**：使用 `:::tabgroup` 语法展示多语言实现。

### 3.3 链接
-   **内部链接**：必须使用 UUID 引用，格式为 `[[uuid|显示标题]]`。
    -   ✅ `[[1234-5678|协程详解]]`
    -   ❌ `[[协程详解]]` (文件名可能变更，UUID 更稳定)
-   **外部链接**：使用标准 Markdown 链接 `[标题](URL)`。

## 4. Linting Guidelines (Linting 指南)

虽然 Agent 无法直接运行 Linter，但生成内容时应遵循以下 `markdownlint` 规则：
-   **MD001**: 标题层级只能逐级递增（H2 -> H3），不能跳级（H2 -> H4）。
-   **MD009**: 行尾不应有空格。
-   **MD022**: 标题上下必须有空行。
-   **MD031**: 代码块周围必须有空行。
-   **MD040**: 代码块必须指定语言。
