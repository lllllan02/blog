# Writing Style Reference

本文件存放 `writing-style` 的细则解释与权威约束。`SKILL.md` 只保留执行入口与自检清单。

## 1. 文档简洁原则（Conciseness）

- **精炼表达**：在保证知识点讲解清晰、完整的前提下，尽量保持语言简单直接。
- **列表化结构**：优先使用有序/无序列表替代长段落，提高信息密度。
- **渐进式披露（Progressive Disclosure）**：
  - **用 Callout 强化**：重点结论、补充说明、注意事项等可用 Callout 强化。
  - **默认折叠扩展**：当内容过长或偏扩展时，优先使用可折叠 Callout（如 `::: [!abstract]- 标题`）收纳。
  - **原子化**：一个 Callout 只讲一个知识点。如果内容简短，优先将核心结论直接写在 Callout 标题中，将补充说明放在内部正文。
  - **常用类型约定（非强制）**：
    - 底层原理/核心解析：`[!abstract]`
    - 面试技巧/提示：`[!tip]`
  - **模块化拆分**：扩展内容篇幅过大时，建议新起一篇文档专项讲解，并在当前文档中用链接引用。

## 2. 标题与元数据规范（Metadata）

- **纯文本标题**：所有层级的标题（H1-H6）严禁使用表情符号（Emoji）。
- **标题命名**：应直接反映内容核心，避免冗长。仅当标题是一个特定“概念”时，推荐使用“中文名称 英文名称”的格式（如：协程栈 Goroutine Stack）；对于问题描述或非概念性标题，保持纯中文简洁即可。

### 2.1 文章/笔记类 frontmatter（权威字段清单）

文章/笔记类文档必须包含以下字段：

- `title`: 页面标题（简洁直观）。
- `aliases`: 包含一个随机 UUID，用于稳定引用。
- `date`: 创建日期，格式 `YYYY-MM-DD HH:mm:ss`（创建新文档时使用当前系统时间）。
- `tags`: 标签列表，优先从标签库选择。
- `order`: 排序权重（数字越小越靠前）。
- `card`: 布尔值。若文档是一个具体的问题/知识点（适合 Flashcards 复习）则设为 `true`；否则设为 `false`。

### 2.2 UUID 与链接规范

- **UUID 约束**：`aliases` 推荐使用 UUID v4（小写、带连字符），并确保全仓库唯一。
- **内部链接规范**：使用 `[[aliases|title]]` 格式，其中 `aliases` 填写目标文档 `aliases` 中的 UUID，`title` 为显示标题。
- **外部链接规范**：统一使用 `[title](url)`。

### 2.3 标签库管理

- **优先选择**：从 `.cursor/data/tags.txt` 选择标签。
- **新增标签**：必须先更新 `.cursor/data/tags.txt`，再用于文档。

## 3. 正文强调与标注（Emphasis）

- **克制原则**：严禁过度强调。每段文字建议只保留 1-2 处最核心的强调。
- **标注方式**：适度使用加粗（`**文本**`）、下划线（`<u>文本</u>`）或 Callout。
- **表情符号**：正文内可适度使用 Emoji 作为列表标记，但需保持专业感，禁止堆砌。

## 4. 排版要求（Formatting）

- **中英文空格**：中英文之间必须保持一个空格（如：Go 语言）。
- **空行规范**：标题与段落、段落与段落之间必须保留一个空行。
- **代码块**：必须指定正确的语言标签（如 ```go）。
- **语法增强**：
  - **代码折叠**：长代码块优先使用 `fold` 标记（如 ` ```go fold="filename" `）。
  - **多维展示**：多语言示例或对比内容优先使用 `:::tabgroup`。
