# 📝 Markdown Formatting & Typography (Markdown 排版与格式规范)

**⚠️ 核心准则：本指南定义了当前项目所有 Markdown 文件的标准排版格式。在生成、撰写或修改文档时，必须严格遵守以下规范。绝不妥协！**

## 1. 元数据 (Frontmatter)
新建或修改文档时，顶部的 YAML Frontmatter **必须**包含以下字段（允许值为空）：
- `title`: 文档标题（**必须是纯中文**，不可译的专有名词除外）。
- `aliases`: 全局唯一的 UUID（作为双链固定标识，**严禁随意更改**）。
- `date`: 创建时间，严格遵守 `YYYY-MM-DD HH:mm:ss` 格式。
- `card`: 布尔值（`true` 或 `false`），标识是否为卡片形式。
- `order`: 数字（选填具体数值，但**必须保留该字段**供排序使用）。
- `tags`: 标签列表（根据内容合理补充相关技术标签）。

*(注：新建文档优先使用项目 CLI 工具 `./clitool new doc|card|wiki "filename"` 以自动生成)*

## 2. 标题与层级
- **禁用一级标题 (H1)**：正文中**严禁**使用 `#`。文章的 H1 已由框架根据 Frontmatter 的 `title` 自动渲染。
- **纯文本标题**：标题中**严禁**使用代码块、加粗、斜体等任何 Markdown 特殊格式。
- **纯中文标题**：二级及以下标题**必须**使用纯中文（例外：标题本身为英文专有名词时允许包含英文）。
- **推荐层级**：使用 `##` (H2) 和 `###` (H3) 划分主要章节，`####` (H4) 仅用于小段落分割。**严禁标题层级跳跃**（如 H2 后直接使用 H4）。

## 3. 文本排版与强调
- **中英混排空格**：汉字与英文字母、汉字与数字之间**必须**保留一个半角空格（如 `通过 API 获取 2 个数据`）。
- **文本强调与高亮**（严格控制使用频率，避免视觉疲劳）：
  - **一般性强调**：使用加粗 `**文本**`。
  - **特定单词/核心词汇重点**：使用黄色高亮 `==词汇==`。
  - **短语或长句重点**：使用蓝色下划线高亮 `<u>这是一段需要划重点的长句子</u>`。

## 4. 引用与链接
- **内部双链引用**：引用项目内其他文档时，**严禁**使用相对路径或普通链接，**必须**使用双链语法：`[[uuid|文档标题]]`。
- **外部来源引用**：参考外部资料时，须在文章开头或引用处使用块引用标明来源：`> [文章标题](URL) (作者/网站名称, YYYY-MM-DD)`

## 5. 特殊语法 (Callout)
- 用于包裹**重点补充内容**或作为文档的**引申扩展**。
- 格式：使用 `::: [!type] 纯中文标题`。
- 要求：详细的写法、折叠形式和支持的类型列表，**必须**查阅并遵守本目录下的参考文档：`[[callout-reference.md]]`。

## 6. Quality Checklist (发布自检清单)
- [ ] 确保无 Markdown 语法错误，所有代码块完全闭合（必须指定语言，如 ````go`）。
- [ ] 确保标题层级无断层，正文无 H1 (`#`)。
- [ ] 确保无行尾多余的空白字符。
